# 『Super MZグラフィック&サウンドテクニック』による Web Emulator 未実装・部分実装監査

調査日: 2026-08-11
対象: `web_emulator/` の現行ソース、テスト、README
主資料: 小笠原佳人ほか『Super MZグラフィック&サウンドテクニック : MZ-2500』ラジオ技術社、1985年12月、国立国会図書館デジタルコレクション PID 12631020、DOI 10.11501/12631020
資料URL: <https://dl.ndl.go.jp/pid/12631020/1/1>

## 結論

README が明記するプリンタ、CMT、SASI、SIO送信、TV制御だけが未実装ではない。グラフィックスとサウンドを誌面のレジスタ動作まで照合すると、優先度の高い不足は次のとおりである。

1. G-CRTCの画面一括消去が、正しいファンクションレジスタ05hではなく、モードレジスタ0Eh bit7に誤接続されている。0Eh bit7はEX側画面を選ぶビットであり、現在の処理はEX値を消してしまう。
2. 同一 `Mz2500` インスタンスで再起動すると、G-CRTCの選択レジスタとBUSY期限、CRTCの選択レジスタと文字サイズ、SIO設定、PPI/PIO、OPN外側のラッチ、Y8950本体などが前回から残る。特に `gde_busy_until_` はCPU時刻だけ0に戻るため、既に終了したBUSYが再起動後に長時間復活し得る。
3. YM2203 Timer A/Bは、ライブラリが要求するタイマ満了コールバックをラッパが実装していないため、満了フラグとCSM発音が進まない。BUSY実装済みというREADME記述だけでは音源全体の実装完了を意味しない。
4. MZ-2000/MZ-80B互換モードは、書籍では独立したメモリ・I/O・画面初期化を持つ主要機能だが、現行コアにはモード状態と切替分岐がない。
5. `cg.rom` はUIとCLIから受け取るがコアで破棄される。したがってROMフォント依存ソフトは未対応である。
6. SSG I/Oポート方向、F6h bit3 MG、拡張GRAM非装着時のレンダラ、Y8950のリセット、ADPCM RAM容量・GPIO・実ソフト再生は、実装または根拠が部分的である。

現行タイトルのゴールデン画像やOPNレジスタ列が通ることと、機械全体の初期値・レジスタ契約が正しいことは別である。現在の回帰は、問題の多くを通らない経路だけを検証している。

SASIのコマンド範囲は一次資料
[Xebec S1410 5.25 Inch Winchester Disk Controller Owner's Manual, document 104524 Rev. C-1 (August 1983)](https://bitsavers.org/pdf/xebec/Xebec_S1410/104524C_S1410Man_Aug83.pdf)

- CMTアナログ音声トラック、SIO同期式を実機コネクタへ運ぶ経路、TV入力、電話、音声合成ボード: 最終効果または機体配線を決める一次資料が不足している。

通常回帰には新しいG-CRTC、YM2203試験と既存の機械レベル・グラフィックス試験8本を追加し、D88試験の実行ディレクトリも固定した。8253のGATE/one-shot修正によりタイトル経路のOPN書込み時刻は8–23 CPU cycle移動したが、1619件のレジスタ番号・値、ブート到達フレーム、2枚の画面ゴールデンは不変であり、時刻を含む決定的ゴールデンを修正後の時系列へ更新した。

### 先行対応表

用語を結果に合わせて後付けしないため、先に作成した対応表を固定した。

- 対応表: [`referent-table-super-mz-unimplemented-audit.md`](referent-table-super-mz-unimplemented-audit.md)

### 判定区分

| 判定 | 意味 |
|---|---|
| 未実装 | 対応する状態・入出力・最終効果の経路がない |
| 誤実装 | 書籍のレジスタまたは動作契約と現行コードが直接食い違う |
| 部分実装 | レジスタ保持や一部モードはあるが、方向制御、タイミング、出力、装着状態などが欠ける |
| 根拠不足 | 値は実装されているが、本書または別一次資料で確定できない |
| 検証不足 | 実装経路はあるが、通常回帰、実ソフト、実機のいずれかで確認されていない |

### 初期状態を分ける四つの時点

本監査では「初期値」を一語で扱わない。

1. 電源投入直後の物理デバイス状態
2. CPUまたは周辺デバイスのRESET直後
3. IPLが初期化してディスクプログラムへ渡す状態
4. BASIC/IOCSの `GINIT`、`SCREEN`、`COLOR`、`PLAY INIT` などを呼んだ後の状態

本書は3と4を複数箇所で説明する一方、全デバイスの1と2を一覧化してはいない。したがって、本書に値がないものを0と仮定してはならない。

## 書籍から確認できた仕様

### G-CRTCの画面消去とEX

誌面58–59頁は、ファンクションレジスタ05hのbit7–6を描画機能として定義し、`10` を「画面クリア」としている。下位4bitは対象プレーンの選択であり、クリア対象は表示窓で示される部分である。[NDLコマ32](https://dl.ndl.go.jp/pid/12631020/1/32)

誌面62–63頁の表示モード表は、0Ehのbit7を含む `93h`、`95h`、`94h`、`9Dh`、`97h` を拡張側を使う正規モードとして列挙している。[NDLコマ34](https://dl.ndl.go.jp/pid/12631020/1/34)

誌面64頁は、BDh読出しbit0を画面クリア実行中の表示とし、クリア中はグラフィックアクセスを禁止して、bit0が0になるまで待つ手順を説明する。[NDLコマ35](https://dl.ndl.go.jp/pid/12631020/1/35)

現行コードは次の点で直接食い違う。

- `core/mz2500.cpp:473-485` は0Eh bit7を消去トリガとして扱う。
- 20h–27hの標準GRAMを無条件に全消去し、05h下位4bitのプレーン選択と08h–0Bhの縦表示窓を使わない。
- 拡張GRAM 28h–2Fhを消去しない。
- BUSYを根拠未記載の3000 CPU cycle固定とする。
- `gde_regs_[0x0E]` へ保存する際にbit7を落とす。
- `core/renderer.cpp:105-167` と `core/gcrtc.h:62-79` はbit7をEXと説明するが、描画アドレス選択でbit7を参照しない。
- `tests/gmode/make_gmode_d88.py:33-45` 自身も `93h` を正規の640×400×16モードとしている。

したがって、これは単なる未テストではない。画面クリアのコマンド、対象範囲、対象プレーン、BUSY時間、EX画面選択が一つの誤った分岐に集約されている。

### 表示モードと互換モード

誌面41頁はMZ-2500、MZ-2000、MZ-80Bの三モードをメモリコントローラで切り替え、互換モードでは使用可能なハードウェア、メモリ配置、グラフィックアクセス、0E4Fh–0E7FhのI/O意味が変わると説明する。[NDLコマ23](https://dl.ndl.go.jp/pid/12631020/1/23)

誌面42頁はF4h–F7hについて、2500、2000、80B各モードで異なる意味を表にしている。[NDLコマ24](https://dl.ndl.go.jp/pid/12631020/1/24)

誌面65頁は2000/80BモードのG-CRTCレジスタ値を示し、誌面82–83頁は互換モード用テキスト画面の初期化をIPLが2500モード中に行い、互換モードへ移った後は変更できないと明記する。[NDLコマ35](https://dl.ndl.go.jp/pid/12631020/1/35)、[NDLコマ44](https://dl.ndl.go.jp/pid/12631020/1/44)

現行 `web_emulator/core/` には機械モードを保持する状態がなく、`core/mz2500.cpp:565-579` はF4h–F7hを常に2500モードのCRTC/表示マスク/文字サイズとして扱う。`B7h` はIPL ROMオーバーレイの切替だけである。MZ-2000/MZ-80B互換動作は現行スコープ外だが、機種機能としては未実装である。

### CRTC、PCG、表示マスク、パレット

誌面72–73頁は、テキストVRAMをブロック38h、PCGと漢字ROMの窓をブロック39hに置き、CFhでPCG0と漢字ROMバンクを選ぶ構成を示す。[NDLコマ39](https://dl.ndl.go.jp/pid/12631020/1/39)

誌面78–79頁はF6hを `MG/GE/RE/BE` とし、bit3 MGはモノクロ出力へのグラフィック重畳、bit2–0は緑・赤・青の出力を制御すると説明する。[NDLコマ42](https://dl.ndl.go.jp/pid/12631020/1/42)

誌面80–81頁は4096色パレットのAEh書込み形式と、YM2203 I/O Port A bit2による本体色信号/パレットボード切替を示す。ただし、RAMの物理RESET値や現行コードの全32バイト初期テーブルそのものは掲載しない。[NDLコマ43](https://dl.ndl.go.jp/pid/12631020/1/43)

付録のGINIT 51hは、画面モード初期化時にGDC、VIEW、POINT X/Y、CBLOCK、PRIORITY、PALETTEを初期化すると明記する。[NDLコマ116](https://dl.ndl.go.jp/pid/12631020/1/116) SCREEN 53hのFFhはスクリーンモードと同時にアクティブグラフ、出力グラフ、アクティブプレーン、出力プレーンを初期化し、COLOR 54hのCF=1はパレットを初期化する。[NDLコマ117](https://dl.ndl.go.jp/pid/12631020/1/117) HVIEW 56h、PRI 5Ch、CBLOCKにも個別の初期化入口がある。[NDLコマ118](https://dl.ndl.go.jp/pid/12631020/1/118)、[NDLコマ121](https://dl.ndl.go.jp/pid/12631020/1/121)、[NDLコマ122](https://dl.ndl.go.jp/pid/12631020/1/122)

この記述から、少なくともソフトウェア契約上は画面初期化が「配列を全0にする」だけではないことが分かる。ただし、GINITが電源投入時に自動実行されるという意味ではない。

### YM2203、SSG、音源初期化

誌面126–127頁は `PLAY INIT` を音源LSIの初期化命令として説明する。[NDLコマ66](https://dl.ndl.go.jp/pid/12631020/1/66)

誌面160–163頁はOPNの21h TEST、24h/25h Timer A、26h Timer B、27hタイマ制御/チャンネル3モードを説明する。27hの開始、満了フラグ設定、フラグリセット、効果音/CSMモードはソフトから観測可能な契約である。[NDLコマ83](https://dl.ndl.go.jp/pid/12631020/1/83)、[NDLコマ84](https://dl.ndl.go.jp/pid/12631020/1/84)

誌面166–167頁はMZ-2500のOPN入力クロックを2MHz、プリスケーラ初期値を1/6とする。[NDLコマ86](https://dl.ndl.go.jp/pid/12631020/1/86)

誌面198–201頁はSSG 00h–0Fhの構成を示し、07hのI/O方向ビットを出力時1、入力時0とする。Port A/Bの値は方向設定を無視して常に同じ意味になるわけではない。[NDLコマ102](https://dl.ndl.go.jp/pid/12631020/1/102)、[NDLコマ103](https://dl.ndl.go.jp/pid/12631020/1/103)

## 初期値・再起動監査

### 現行ブート経路が明示的に初期化するもの

`core/dummy_ipl.cpp:41-93` と `142-190` は、ダミーIPLと実IPLの両経路で次を初期化する。

- RAM、VRAM、PCGを0クリア
- FDC、YM2203、マウス
- SIO DTRと受信キュー
- 8253状態、割込保留、割込ベクタ、周期tick
- PIO port A、ジョイスティック押下マスク
- CRTCレジスタ全体、CRTC 00h=`05h`、窓の「未書込み」フラグ
- F6h=`07h`
- G-CRTCレジスタ全体を0
- MZ-1M10用とする32バイト表、`palette_written_=false`
- OPN外側のレジスタ影配列

このうち、本書で直接裏付けられるのは機能とソフトウェア初期化の存在であり、`CRTC 00h=05h`、F6h=`07h`、RGB444全表、RAM/VRAM/PCG全0が「実IPL引渡しの厳密な値」であることまでは本書単独で確定できない。

### 同一インスタンスで残る状態

次の状態はメンバ構築時には初期化されるが、二つのブート関数では戻されない。保持が実機仕様と確定しているものではなく、単にコードが触れていないものを含む。

| 状態 | 影響 | 判定 |
|---|---|---|
| `crtc_index_`、`font_size_` | 再起動後のF5h書込み先、8/16ライン表示が前ソフト依存 | RESET漏れの可能性が高い |
| `gde_index_`、`gde_autoinc_` | 再起動後最初のBDhが前回選択レジスタへ入る | RESET漏れ |
| `gde_busy_until_` | CPU cycleを0へ戻した後、過去の絶対期限が未来になる | 明確な再起動バグ |
| `gvram_latch_[4]` | BCh–BFhの生プレーン読出しが前回値を返す | RESET漏れ |
| SIO `regs[]`、`pointer` | 受信キューだけ消え、WR設定と選択状態が残る | RESET漏れ |
| `opn_addr_`、`fm_keyon_` | YM2203本体はresetされるが外側の影が乖離する | 部分リセット |
| `ppi_[3]`、`pio_ctrl_[2]`、`joy_enable_` | キーボード行、BEEP、PIO設定等が前回依存 | RESET漏れまたはリセット種別未定義 |
| `bank_mode_` | 実メモリマップは再設定されるがラッチ値だけ残る | 内部状態不整合 |
| `rtc_mode_`、`rtc_bank1_` | バンク選択、アラーム関連ラッチが残る | 保持条件を別資料で要確認 |
| `last_vblank_frame_` | 特定タイミングの再起動で最初のVBLANKを落とし得る | RESET漏れ |
| Y8950本体、タイマ、音声リング、I/Oラッチ | ブート経路が `adpcm_.reset()` を呼ばない | 明確な部分リセット |

さらに `core/opn.cpp:48-60` の `OpnYm2203::reset()` は `beeper_` を0に戻さない。外側の `ppi_[2]` も残るため、前ソフトのBEEP DCレベルが再起動後も音声ミックスへ残り得る。

### 画面初期化の代替ヒューリスティック

`core/gcrtc.h:33-41` は、CRTCのpower-on値が不明でダミーIPLもファームウェアのCRTC設定を再現しないため、縦横窓が一度も書かれていなければレジスタ値に関係なく全画面表示する。この区別は既存タイトルのフラッシュ防止には有効だが、実機状態の実装ではなく互換ヒューリスティックである。

G-CRTC側には同じ「未書込み」区別がない。ダミーIPLはGDE全体を0にするため、モードや表示窓をIPL引渡し値に依存するプログラムはグラフィック層が消える。実IPLが実際に書く値をI/Oトレースで採取し、ダミーIPLの引渡し表として固定する必要がある。

### MZ-1M10パレットの初期化矛盾

`core/mz1m10.h:12-23` は「ハードウェアはRAMをクリアせず、ファームウェアが全表を書く」と説明する。一方、二つのブート経路は実IPL実行前を含めて毎回同じ表を先に投入する。これは最終的なIPL引渡し状態を近似するダミーIPLではあり得るが、実IPL経路の電源/RESET状態とは分けるべきである。

`tests/gmode/check_palreset.sh:1-12` のコメントは「ブート経路がRGB444エントリを0にする」と書くが、現行コードは全表をseedする。試験が見るのは `palette_written_` によるデジタル/ボード切替だけで、未書込みパレットエントリの内容は観測しない。初期値試験としては不足している。

### 「全オプション装着」が既定の構成

初期値と機器構成も分ける必要がある。`core/banked_memory.h:88-89` と `core/mz2500.h:402-404` は、拡張RAM、MZ-1R27、MZ-1M10、MZ-1E35、MZ-1R37をすべて装着状態で構築する。Web UIも `web/emulator.js:301-319` で、保存値がなければ全項目を装着済みにする。

これはデバイスのRESET値ではなく、エミュレータの互換性プリセットである。意図的な方針としては成立するが、未装着機でしか通らない分岐、4色640×400、デジタルパレット、オープンバス、拡張GRAM不在描画を既定回帰が避ける。報告やテストでは「標準構成」と「全オプション構成」を別プロフィールとして明記すべきである。

## サウンド詳細監査

### YM2203 Timer A/BとCSM

本書が説明するTimer A/Bの開始、満了フラグ、リセット、CSMは現行ラッパでは完結しない。

- `core/opn.h:66-70` はBUSY用 `ymfm_set_busy_end` だけをoverrideする。
- vendored ymfmの `ymfm.h:523-527` は、ホストが `ymfm_set_timer()` を実装し、期限後に `engine_timer_expired()` を呼ぶ責任を明記する。既定実装はno-opである。
- ymfmの `ymfm_fm.ipp:1473-1517` は、満了通知を受けて初めてTimer A/B statusとCSM key-onを更新する。
- `core/opn.cpp:67-70` のstatus読出しは時刻を保存して現在statusを返すだけで、タイマ期限を進めない。

よってTimer A/Bの満了statusとCSMは、疑いではなく未実装である。YM2203 IRQをMZ-2500の割込コントローラへ結ばないこととは別問題であり、IRQ線がなくてもソフトはstatusをポーリングできる。

### SSG I/O Port A/B

`core/mz2500.cpp:513-522` は、OPNへ書いたレジスタ0Ehを外側の `opn_regs_` へ常に保存し、パレット切替とマウス切替へ使う。SSG 07hでPort Aが入力に設定されていても配線効果が発生する。

`core/opn.cpp:72-75` は、現在アドレスが0Fhなら方向に関係なく常に固定入力 `3Fh` を返す。出力設定時には本来ラッチ値を読むべきであり、Port A入力時はymfm interfaceの既定値0に落ちる。誌面200頁の方向制御と一致しない。

必要なのは、`ymfm_external_read/write(ACCESS_IO, 0/1)` をMZ-2500側配線へ接続し、07hの方向判定をymfmに任せることである。外側の影配列は表示・マウス用デバッグ値として使えても、方向制御を迂回してはならない。

### OPN、BEEP、初期値

- 2MHz入力クロックは `core/opn.h:1-13` と本書が一致する。
- BUSY窓と音声生成は実装され、現行タイトルのOPN書込み列と音声比較がある。
- `OpnYm2203::reset()` はYM2203本体と音声リングを戻すが、`beeper_` を戻さない。
- BEEPは実際には8255 Port C bit2、E2h/E3hで駆動される。`opn.h:55-57` の「port CAh」はコメント誤りである。
- `PLAY INIT` 相当のファームウェア処理をダミーIPLが提供するわけではない。ディスク側が必要なOPNレジスタを初期化する前提になっている。

### Y8950/ADPCM

本書の全文検索では `ADPCM`、`Y8950`、`MZ-1E35` に該当コマがなかった。本書から「未装着」「仕様なし」と結論してはならず、ボードのI/O資料、回路図、Yamahaデータシートが必要である。

現行コードから確認できる境界は次のとおりである。

| 項目 | 現状 | 判定 |
|---|---|---|
| Y8950 FM/delta-T | ymfm経由で生成 | 実装あり |
| タイマ | 満了を観測時に最大1回だけ処理し、観測時刻から再計算 | 部分実装、非サイクル精度 |
| ADPCM RAM | 32KB固定、範囲外read=00h/write無視 | 暫定 |
| GPIO/LINE/MIC | I/Oラッチのみ | 最終効果未実装 |
| RESET | `AdpcmY8950::reset()` 自体はあるがブート関数が呼ばない | 部分実装 |
| RAM保持 | `reset()` でもRAMは消さない | 実機保持条件を要確認 |
| OPNとの相対音量 | `OUT_GAIN` は未校正の推測 | 根拠不足 |
| 実ソフト再生 | 装着判定は通るがdelta-T再生未確認 | 検証不足 |

`core/adpcm.cpp:10-17` は相対音量が未校正で、両チップのピーク同時加算がホストclamp前に±2へ達し得ることを自ら記録している。単体テストは人工レジスタ列と数学的加算を確認するだけで、実基板のアナログ比率を確定しない。

### 8253と音楽割込

8253 ch0の割込用途は実装され、現行MZSDが利用する。ただし `core/mz2500.cpp:564` のF0hはno-opであり、F1h–F3hはdefaultへ落ちる。設計書が列挙するF0h–F3h GATEパルスの物理効果は実装されていない。カウントの開始をreload書込みへ畳んでいるため、GATEを明示的に使うソフトとは挙動が異なる。

### 別売音声合成ボード

本書は `VOICE`/`VOICE @` を別売音声合成ボード用命令として挙げ、誌面204–205頁に制御信号を載せる。現行コアには音声合成状態、0Eh/0Fh制御、音声出力の経路がない。READMEの未実装一覧にも載っていないが、書籍収録範囲との比較では未実装オプションである。

## 次に集めるべき一次資料と試験

### 実装前に必要な資料

1. G-CRTCのI/Oマップ原本: 05h画面クリアの開始条件、対象プレーン、縦窓境界、EX画面、BUSY実時間。
2. 実IPLのI/Oトレース: CRTC 00h–0Ch/80h–8Fh、G-CRTC 00h–18h、F6h、F7h、OPN 07h/0Eh/0Fh、8255/PIO/SIOの引渡し値。
3. YM2203公式データシート: RESET後レジスタ、Timer A/B、CSM、SSG I/O方向。
4. MZ-1E35資料とY8950公式データシート: RAM容量、RESET線、GPIO、LINE/MIC、出力レベル。
5. プリンタ、SASI、TV、音声合成ボード各I/O資料。

### 最小の受入試験

1. G-CRTC 05h=`10xxxxxx` で、指定プレーンと縦表示窓だけが消え、BDh bit0が一定期間立つ。
2. 0Eh=`15h/95h`、`14h/94h`、`1Dh/9Dh`、`17h/97h` を切り替え、標準/拡張画面の内容が入れ替わる。
3. 拡張GRAMをOFFにして、CPU読出しとレンダラの両方が不在状態を示す。
4. 全リセット対象へ毒値を書き、同一インスタンスでダミーIPL/実IPLを再起動し、定義したRESET値または保持値へ戻る。
5. YM2203 Timer A/Bを短周期で開始し、status set/resetとCSM key-onをCPU cycle基準で検証する。
6. SSG 07hでPort A/Bのinput/outputを切り替え、外部入力値、出力ラッチ、パレット/マウス配線効果を確認する。
7. Y8950を再生中に再起動し、再生、status、timer、音声リングが定義状態へ戻る。RAM保持は別アサーションにする。
