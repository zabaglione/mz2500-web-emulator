# ゲームパッドとジョイスティックトリガの対応

実機のMZ-2500用ジョイスティックは2ボタン（トリガ1・トリガ2）である。ブラウザのゲームパッドは
ボタンが多いので、どのボタンをどちらのトリガに割り当てるかを決める必要がある。

この文書は、その既定値をどう決めたか、そしてなぜ**もう変えないか**を記録する。

## ハードウェアの事実

ポートEFh（読み出し、負論理）のビット割り当ては Oh!MZ「ハードウエア内部解析」章 202ページの
I/O表が一次資料である。

| ビット | 意味 |
|---|---|
| b5 | **トリガ1** |
| b4 | **トリガ2** |
| b3-b0 | 方向スイッチ |

つまり **トリガ1 = 0x20、トリガ2 = 0x10**。この番号付けは NEKO CAN RUN の入力ルーチン
（`bit 5,c` をトリガ1として読む）とも一致する。

なお **EmuZ-2500 の `--joy-pulse` ヘルプは `10 trigger-1 / 20 trigger-2` と表示する**が、
これは上の表と逆である。EmuZ内部の呼び名の問題で、ポートに出るビット自体は同じ。

## EmuZ-2500 で「○ = ダッシュ、× = ジャンプ」になっていた理由

設計上の意図ではなく、**名前のずれが2つ重なった結果**である。

1. EmuZ は SDL の GameController 規約で拾ったボタンを割り当てる。`A`（PSパッドの `×`）が主ボタン、
   `B`（`○`）が副ボタン。
2. EmuZ は主ボタン `A` をポートEFhの **b4** に流し、それを自分では「trigger-1」と呼んでいる。
   しかし b4 はハードウェア上は**トリガ2**である。
3. NEKO CAN RUN は b4 をトリガ2として読む。NEKOの既定 (`pf_swap = 1`) はトリガ2 = ジャンプ。

結果、`×`（EmuZの主ボタン）→ b4 → NEKOのジャンプ、`○` → b5 → ダッシュ、となった。
ボタンの押しやすさを考えた選択ではない。

## 既定値

**トリガ1 = `A / ×`、トリガ2 = `B / ○`。**

理由は単純で、パッドの主ボタン（標準マッピングのインデックス0）を実機の主ボタンである
トリガ1に対応させる、というだけである。エミュレータ側でソフトの操作性を先回りして
調整することはしない — どのトリガが何をするかはソフトの決定事項であり、
NEKO CAN RUN はタイトル画面の CONFIG でそれを入れ替えられるようにしている。

この既定値で NEKO CAN RUN を遊ぶと、`×` = ダッシュ、`○` = ジャンプ になる
（NEKOの既定 `pf_swap = 1` によりトリガ1 = ダッシュのため）。

## 変更したい場合

既定値は動かさない。好みは画面左の「ゲームパッドのボタン割り当て」で変更でき、
設定はブラウザに保存される（`localStorage` の `mzw_pad_trig1` / `mzw_pad_trig2`）。
