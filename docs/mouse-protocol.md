# MZ-2500 マウス（MZ-1X10）の接続とプロトコル

実測で確定した内容の記録。資料に載っていない部分は、実機ファームのマウスドライバに
バイト列を与えて反応を測る方法で決めた。

## 接続

| 項目 | 内容 | 出典 |
|---|---|---|
| 経路 | Z80B SIO チャンネルB（**A2h**=データ、**A3h**=レジスタ選択/コマンド/ステータス） | Oh!MZ p180 |
| 切替 | YM-2203 ポートA の b3=1 でRS-232C 25ピン側からマウスへ | Oh!MZ p299 |
| 制約 | ジョイスティック2ポート目とLSIポートを共用（同時使用不可） | 同 |
| API | IOCS **7Ah（MOUSE）** | Oh!MZ p238 |

## ファーム側の動作（トレースで確認）

BASICで `mouse 0` を実行したときのSIOチャンネルBへの書き込み。

```
WR0 <- 30h   エラーリセット
WR1 <- 18h   全受信文字で割込み
WR2 <- F8h   割込みベクタ
WR3 <- C1h   8ビット/文字、受信イネーブル      ← 起動時のRS-232C初期化はC0h（受信オフ）
WR4 <- 44h   x16クロック、ストップ1
WR5 <- 60h   8ビット/文字
```

以降、**8253タイマ割込みハンドラの中で毎フレーム2回**、DTR（WR5 b7）をトグルする。

```
WR5 <- 68h   DTR off
WR5 <- E8h   DTR on
```

これがマウスへのストローブ。ドライバはポーリングを一切せず、返答は**SIO受信割込み
（ベクタF8h）**で受け取る。

## パケット形式（実測）

**1パケット = 3バイト。**

| バイト | 意味 | 挙動 |
|---|---|---|
| 0 | ボタン | **b0 = ボタン1、b1 = ボタン2**（押下で1）。素通しで格納 |
| 1 | **X移動量** | **符号付き8ビット**、累積される |
| 2 | **Y移動量** | **符号付き8ビット**、累積される |

移動量が符号付きであることの実測（X座標を128にしてから負値を与える）:

| 注入 | 結果のX |
|---|---|
| `00 40 00` ×2 | 80h (128) |
| 続けて `00 FF 00`（-1） | **7Fh (127)** |
| 続けて `00 01 00`（+1） | 81h (129) |
| 続けて `00 80 00`（-128） | **00h (0)** |

バイト0は加工されず、ドライバの **4ABF** と **4B80** の両方にそのまま格納される
（`FF` を与えると両方 FFh になる）。

ドライバの座標はCPUアドレス **4ABB（X）/ 4ABD（Y）**、ステータスは **4ABF**
（マップ07、物理 0EABB / 0EADD / 0EABF）。`mouse(0)` の戻り値は4ABBと一致する。

実測データ:

| 注入バイト列 | 4ABB(X) | 4ABD(Y) | 4ABF(状態) |
|---|---|---|---|
| なし | 00 | 00 | 00 |
| `00 05 00` | **05** | 00 | 00 |
| `00 05 00` ×2 | **0A** | 00 | 00 |
| `00 05 00` ×3 | **0F** | 00 | 00 |
| `00 00 05` | 00 | **05** | 00 |
| `00 00 05` ×2 | 00 | **0A** | 00 |
| `05 00 00` ×2 | 00 | 00 | **05**（累積せず） |
| `7F` ×8 | FE | C7（画面下端でクランプ） | 7F |

1〜2バイトだけでは何も起きず、3バイト揃って初めて反映される。

ボタンビットの実測（バイト0の各ビットを立てて `print mouse(2,<番号>)` の表示が
変わるかを見た）:

| 立てたビット | mouse(2,1) | mouse(2,2) |
|---|---|---|
| b0 (01h) | **変化する** | 変化なし |
| b1 (02h) | 変化なし | **変化する** |
| b2〜b7 | 変化なし | 変化なし |

## ホスト側の移動量補正（実装方針）

現代のマウスは解像度もレポートレートもMZ-1X10と桁が違うので、ブラウザの
`movementX/movementY` をそのまま流すと使い物にならない。**補正はホスト入力側で行う。**

MZ側にも移動比率の設定はある（IOCS A=3/4、BASIC `mouse 3,<方向>,<比率>`、既定8）が、
**これはソフトが決める設定なのでエミュレータが触ってはいけない**。
[[emulator-fidelity-over-ergonomics]] と同じ理由で、勝手に変えると
ソフト側の設定機能と二重になる。

したがって:

- ポインタロック中の `movementX/movementY` を**感度（倍率）**で拡縮する
- 端数は累積する。1パケットぶんに満たない移動を捨てない
- 1パケットに載る移動量の範囲でクランプし、余りは次のパケットへ繰り越す
- 感度は左ペインの「マウス」パネルで変更でき、ブラウザに保存する。既定は等倍相当

捕捉と解放:

- 画面クリックで捕捉（ポインタロック）
- **Esc で解放**（ブラウザ標準。この Esc は MZ 側へ送らない）
- ドライブベイの「マウス」ボタンで捕捉自体の入切と現在状態の表示（「テンキー」ボタンと同じ作り）

## 調査に使った道具

- `--sio-b BYTES:FRAME` — SIOチャンネルBに16進バイト列を流す
- `MZ_TRACE_ALL=1` + `--trace-io` — 全ポートをトレース（DTRストローブはこれで発見）
- `--phys-dump EABB:5` — ドライバの座標変数を直接読む
